# v0

Profiled provider: [`Sources/Pulse/Providers/Profiled/V0UsageService.swift`](../../Sources/Pulse/Providers/Profiled/V0UsageService.swift). User setup: [../setup/v0.md](../setup/v0.md).

- **Credential:** a v0 Platform API key the user pastes.
- **Route:** `GET https://api.v0.dev/v1/user/billing`, then `GET https://api.v0.dev/v1/rate-limits`, both bearer. The rate limit is best-effort.
- **Reply:** billing is `{ billingType: "token", data: { balance: { total, remaining }, billingCycle: { end }, onDemand: { balance } } }` or `{ billingType: "legacy", data: { limit, remaining?, reset? } }`; any other type is unreadable. Rate limit: `{ limit, remaining?, reset? }`. Times are Unix seconds or milliseconds (≥ 10¹² read as ms); zero is no reset.
- **Windows:** billing → `.credits` (v0's own units over a cycle whose length is not stated; 30 days as a sort key), rate limit → `.messages` (a count with a reset and no stated length; one day as a sort key). Used is `limit − remaining`, both reported. A missing remainder leaves that window off — the size alone is not a percentage.
- **Left out:** the on-demand balance (a number in no named unit; CodexBar also declines to call it dollars); CodexBar's optional project scope (`?scope=`), which needs a second field; the free plan's daily allowance, which CodexBar does not read either.
- **Evidence:** second-hand. The shapes come from CodexBar's v0 plugin and its tests (MIT); no live account has been read. Fixtures: `Tests/PulseTests/Fixtures/v0-*.json`.
