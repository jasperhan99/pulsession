# Sakana AI

Profiled provider: [`Sources/Pulse/Providers/Profiled/SakanaUsageService.swift`](../../Sources/Pulse/Providers/Profiled/SakanaUsageService.swift). User setup: [../setup/sakana.md](../setup/sakana.md).

- **Credential:** `sessionCookie(host: "console.sakana.ai", cookies: ["__Secure-authjs.session-token"])`. The console signs in with Auth.js; its sign-in page sets `__Host-authjs.csrf-token` and `__Secure-authjs.callback-url` (seen 2026-09-25), so the session cookie is Auth.js's `__Secure-authjs.session-token`. **Unverified** against a signed-in browser. CodexBar takes a whole pasted `Cookie:` header and names no cookie. Auth.js splits a large session into `…session-token.0`, `.1`; a split session has no unsuffixed cookie and is not found by the shared keep-filter (see below).
- **Route:** `GET https://console.sakana.ai/billing` (the limits) and, concurrently, `GET https://console.sakana.ai/billing?tab=payAsYouGo` (the balance, which only that tab renders on the server). `Accept: text/html`, `Accept-Language: en-US` (the labels matched are English). Ephemeral session with no cookie store and **no redirects followed** (`NoRedirects`).
- **Status:** a 3xx (signed out: the console redirects to `/login`) or 401/403 → `.sessionExpired`; the rest through `ProfileHTTP.classify`. The balance tab is best effort: any failure leaves the balance off.
- **Shape (HTML):** each limit is a `<p>5-hour</p>` / `<p>Weekly</p>` label followed, before the next label or `data-slot="card"`/`"card-title"` div, by `<p>NN% used</p>` and `<p>Resets on June 23, 2026 at 2:53 PM</p>`. The reset is server-rendered in **UTC** (`MMMM d, yyyy 'at' h:mm a`, `en_US_POSIX`). The plan is the first `<span>` of the first `data-slot="card-title"` div. The balance is the `tabular-nums` `<p>` after `<h2>Credit balance</h2>`.
- **Windows:** `5-hour` → `.fiveHour` (5 h), `Weekly` → `.weekly` (7 d), both stated lengths. A limit whose percentage is missing, unparseable or negative is left off; the other stands. A reset that doesn't parse is left off, not the limit.
- **Balance:** only when the figure carries a `$` → `creditBalance` and `creditRemaining` (USD). A bare number is left off rather than given a currency.
- **Reasons:** neither limit nor balance on the page → `.unreadableReply`.
- **Left out:** the price label beside the plan (`$20/mo`) — a price, not a plan name. The pay-as-you-go "Total" for the selected date range — spend with no limit; Pulse has no place for it yet. CodexBar rejects the whole page when a percentage is over 100; Pulse keeps it and marks the limit exhausted.
- **Needs (shared, not added):** the shared cookie filter `ProviderProfile.keep` requires the first named cookie exactly, so an Auth.js session split into numbered chunks can't be imported.
- **Evidence:** second-hand. The markup comes from CodexBar's Sakana provider and its tests (MIT); no signed-in page has been read. The fixtures are inline in `Tests/PulseTests/SakanaTests.swift`.
