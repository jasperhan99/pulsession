# Alibaba Coding Plan

Profiled provider: [`Sources/Pulse/Providers/Profiled/AlibabaCodingPlanUsageService.swift`](../../Sources/Pulse/Providers/Profiled/AlibabaCodingPlanUsageService.swift). User setup: [../setup/alibaba-coding-plan.md](../setup/alibaba-coding-plan.md).

- **Credential:** an API key the user pastes. Nothing is read from this Mac.
- **Route:** `POST {console}/data/api.json?action=zeldaEasy.broadscope-bailian.codingPlan.queryCodingPlanInstanceInfoV2&product=broadscope-bailian&api=queryCodingPlanInstanceInfoV2&currentRegionId={region}`, JSON body `{"queryCodingPlanInstanceInfoRequest":{"commodityCode":…}}`, the key as `Authorization: Bearer`, `x-api-key` and `X-DashScope-API-Key`, with the console's `Origin` and `Referer`.
- **Sites:** international (`modelstudio.console.alibabacloud.com`, `ap-southeast-1`, `sfm_codingplan_public_intl`) first; China mainland (`bailian.console.aliyun.com`, `cn-beijing`, `sfm_codingplan_public_cn`) when the first answers 401/403/404, refuses the key in the body, lists no plan, or has no figures. No setting chooses; `requiresScopeMatch` is false. When both fail, a refusal is reported only if both refused.
- **Reply:** nested, sometimes with the real reply as a JSON string inside a field (expanded first). `codingPlanInstanceInfos[]` lists plans; the one whose `status` is `VALID`/`ACTIVE` (or whose end time is ahead) is read, and with several plans an expired one's figures never stand in. Figures come from `codingPlanQuotaInfo`.
- **Windows:** `per5HourUsedQuota`/`per5HourTotalQuota` (5 h), `perWeekUsedQuota`/`perWeekTotalQuota` (7 d), `perBillMonthUsedQuota`/`perBillMonthTotalQuota` — a billing month, so 30 days is a sort key only (`reportsLength: false`). Resets from `…NextRefreshTime` (epoch ms). Plan name from `planName`/`instanceName`/`packageName`.
- **Figures:** used ÷ total, both as reported. A missing used figure, a negative one, or a missing/zero total drops that window. A reset in the past is dropped (CodexBar moves it forward five hours; that is a guess). None left is "No limits reported"; an empty or all-lapsed plan list is "no plan".
- **Errors in a 200:** a numeric `statusCode`/`code` of 401/403, or a message about the API key, is a refused key (tried on the other site). `ConsoleNeedLogin` means the route wants a console session for this account: shown as a refused key and not retried.
- **Left out:** CodexBar's primary route is a browser session on the console (with a `sec_token` scraped from the page and a site chosen in its settings). Pulse's session credential reads one host, and the two sites' sessions live on `alibabacloud.com` and `aliyun.com`; that route needs a site picker Pulse does not have, so only the key route is implemented. CodexBar's "plan visible, no figures" row is not drawn.
- **Evidence:** second-hand. The shape comes from CodexBar's Alibaba provider and its tests (MIT); no live account has been read. The fixture is `Tests/PulseTests/Fixtures/alibaba-coding-plan-instances.json`.
