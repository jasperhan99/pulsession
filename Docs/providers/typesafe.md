# TypeSafe

Profiled provider: [`Sources/Pulse/Providers/Profiled/TypeSafeUsageService.swift`](../../Sources/Pulse/Providers/Profiled/TypeSafeUsageService.swift). User setup: [../setup/typesafe.md](../setup/typesafe.md).

- **Credential:** `sessionCookie(host: "console.typesafe.ai", cookies: [])` — **a pasted Cookie header.** The console's session cookie is not named anywhere: CodexBar deliberately sends every cookie scoped to `console.typesafe.ai` / `.typesafe.ai` for the `/settings/billing` path rather than assume a name, and the console is behind Cloudflare, so the name could not be learned here. `ProviderProfile.keep` keeps only named cookies and returns nothing for an empty list, so **Read from browser finds nothing** and the user pastes the header (a leading `Cookie:` is stripped). An inference API key does not replace the console session.
- **Missing shared piece:** a session import that keeps every cookie for a host (and its path), for services whose session cookie has no known name. With it, `cookies` would stay empty and Read would work.
- **Route:** a Next.js server action on the billing page.
  1. **Find the action id** (only when none is cached, or it went stale): `GET https://console.typesafe.ai/settings/billing` (`Cookie`, `Accept: text/html`); 401/403 → `.sessionExpired`; a page carrying the `(auth)` → `login` route (escaped or not) → `.sessionExpired`. Then each same-origin `<script src>` ending `.js`, in order, at most 60, **without the cookie**, until one matches `"<40+ hex>"` within 150 characters before `"getBillingOverviewResult"`. A 429 or 5xx there stops the search with that reason; nothing found → `.unreadableReply`. The id is kept in memory for 12 hours.
  2. **Call it:** `POST https://console.typesafe.ai/settings/billing` with `Cookie`, `Origin: https://console.typesafe.ai`, `Next-Action: <id>`, `Accept: text/x-component`, `Content-Type: application/json`, body `[]`. A read; it changes nothing. A 404 with a cached id means the console was redeployed: the id is found again once and the call repeated. (CodexBar keys this on the `x-nextjs-action-not-found: 1` header; `ProfileHTTP.Reply` carries no headers, so any 404 is taken as that.)
- **Reply:** React's line format, `id:payload` per line; the first line whose JSON has an `ok` key is the result. `ok` not `true` → `.serverError`. `data.billing.balance` must be a finite number, or the reply is unreadable. A login landing here too → `.sessionExpired`.
- **Windows:** none.
- **Balance:** `billing.balance` as USD (`creditRemaining`, `reportsSpendableBalance`), zero included. The reply carries no currency code; the console shows dollars.
- **Plan:** `billing.plan` — `free_plan` → "Free", otherwise words split on `_`/`-` and capitalised.
- **Left out:** `billing.spent` and `cycleLabel` (spend with no limit — nowhere to show it yet); `billing.credits[]` (each grant's `amount`, `remaining`, `expiresAt` — a grant expires rather than resets, and the balance already sums them); `resetsInDays` (not a quota reset, as CodexBar notes too); redirect rejection — `URLSession` follows redirects, so a redirect to sign-in is caught by the login-landing check instead of the status.
- **Icon:** none in Lobe Icons; the generic `extension` mark.
- **Evidence:** second-hand. The flow and shapes come from CodexBar's TypeSafe plugin (`typesafe.ts`), `TypeSafeCookieImporter` and their tests (MIT); no live account has been read, and the console could not be reached without a browser. Fixture: `Tests/PulseTests/Fixtures/typesafe-billing-result.json`; the page, chunk and action exchange in the tests is a stub.
